# Как тестировать античит — и почему `.mcpack` не может быть читом

## Коротко

**`.mcpack` — это ресурс-пак. Это не программа.**

Он умеет менять **только внешний вид**: текстуры, модели, звуки, шрифты. Он
не исполняет код, не имеет доступа к сети и не может отправить на сервер ни
одного пакета. Движок Bedrock **не даёт** ресурс-паку API для управления
движением, боем или взаимодействием с блоками — такого API не существует
в принципе.

Поэтому «чит для тестов античита в виде `.mcpack`» с KillAura, Fly и Nuker —
это не сложная задача, а **невозможная**. Не «сложно сделать», а физически
нечем: в формате нет механизма, который бы это выразил.

Дальше — что реально делают чит-клиенты, и чем их тогда тестировать.

---

## Что на самом деле делают чит-клиенты для Bedrock

Они работают на другом уровне. Три подхода:

| Способ | Что это | Почему `.mcpack` не подходит |
|---|---|---|
| **DLL-инъекция** | Патч в память клиента (Horion, Solstice) | Нужна нативная библиотека под Windows. В `.mcpack` нет исполняемого кода |
| **Прокси-клиент** | Свой клиент, который говорит по RakNet/NetherNet и шлёт пакеты сам (ProtoHax, Minced) | Это отдельная программа, а не пакет ресурсов |
| **Сторонний лончер** | Клиент, собранный из модифицированного исходника | То же |

Ключевое: чит живёт там, где **формируются пакеты**. Ресурс-пак к этому
слою доступа не имеет. Поэтому `.mcpack` с «функциями» может изображать
читерский интерфейс (кнопки, оверлеи), но нажимать их будет некому —
логики нет.

Отдельно: с версии **1.21.50/1.21.60** Mojang закрыла движение-хаки на
Realm и серверах (`.tp`, jetpack, полёт) — старые клиенты вроде Horion
перестали работать в этом классе сценариев. Это делает «тестовый чит»
ещё менее реалистичным: актуальный чит сегодня — это либо DLL под
Windows-клиент, либо самостоятельный прокси-клиент.

**Вывод: в формате `.mcpack` я могу дать только визуальную часть.** Всё
остальное — обещание, которое нельзя выполнить, и я не буду его давать.

## Что я собрал: `VoidAC-Test-XRay.mcpack`

Полностью рабочий ресурс-пак. Проверяет **локальные визуальные векторы** —
те, что клиент рисует сам и которые сервер не контролирует.

**Внутри:** 11 блоков-заполнителей (камень, глубинный сланец, земля,
гравий, андезит, диорит, гранит, туф, кальцит, незерак, булыжник) получают
полностью прозрачную текстуру с `alpha_test`. Руды не тронуты — на их фоне
видно, что пак работает.

**Что проверяет по вашему античиту:**

| Функция AC | Проверяется паком? | Как |
|---|---|---|
| `anti-esp` (скрытие сущностей за стенами) | **да, косвенно** | С паком вы видите сквозь землю. Если VAC скрывает сущность за стеной, вы её **не увидите даже с X-Ray**. Если видите — anti-esp утечка |
| Встроенный Anti-Xray (обфускация руды) | **да** | Сервер подменяет руду на клиенте. С прозрачными текстурами видно, работает ли подмена: настоящая руда не должна проглядывать |
| `reach`, `killaura`, `speed`, `fly`, `automine` | **нет** | Пакет не шлёт пакеты |

**Установка:** открыть файл двойным щелчком → Minecraft импортирует → Настройки
→ Глобальные ресурсы → активировать.

**Важно:** с прозрачным камнем пещеры рисуются чёрными. Это не поломка —
выкрутите «Яркость» на максимум, иначе покажется, что пак не работает.

**Сборка из исходника:** `python3 test-kit/build_testpack.py` (генерирует
текстуры и манифест, ничего не скачивает).

## Чем реально тестировать остальные проверки

Пакет не подходит, но задача решаема — просто другими средствами.

### 1. Команды самого античита — то, что уже есть

Самый надёжный путь, потому что он проверяет **ваш** код, а не чужой:

```
/vac info <ник>        профиль: устройство, ввод, улики по каждой проверке
/vac list              кто под наблюдением
/vac check <ник>       детали по проверке
/vac reload            применить конфиг без рестарта
```

Тест «в одну сторону»: зайдите с телефона и с ПК, сравните `/vac info` —
определитель ввода должен показать разные категории.

### 2. Режим наблюдения — обязательно первым шагом

```yaml
enforcement: false
```

Доказано автотестом (9 точек коррекции под гейтом): в этом режиме ни один
чит не отменяется и не наказывается, только пишутся алерты. Это и есть
безопасный способ «прогнать читера» — вы видите, что проверки сработали,
но никого не кикнуло.

**Порядок:** `enforcement: false` → прогнать сценарии → сверить алерты с
ожидаемыми → только потом `true`.

### 3. Сценарии, которые можно воспроизвести без чита

Большинство проверок ловится на **легальных действиях**, если их ускорить
или повторить машинно:

| Проверка | Как воспроизвести легально |
|---|---|
| `automine` | Копать только руду подряд в шахте 20+ секунд |
| `minebot` | Макрос автокликера (любой, даже мышь с ПО) по блокам |
| `buildpattern` | Ставить блоки в один и тот же узор 8+ раз |
| `fastbreak` / `fastplace` | Зажать кнопку, высокий CPS |
| `reach` | Бить по краю хитбокса, стоя на месте |
| `velocity` | Прыгать в момент отброса |
| `speed` / `fly` | Элитра, лёд, лодка — легальные ускорения, ложных быть не должно |

Это **лучший** тест: если проверка срабатывает на легальном действии — это
ложное срабатывание, и оно хуже пропущенного чита.

### 4. Если нужен настоящий чит-клиент

Для полноценного краш-теста (KillAura, Fly, Nuker) нужен клиент того же
класса, что у ваших нарушителей. На сегодня это **Windows DLL** (Horion,
Solstice) или **прокси-клиент** (ProtoHax, Minced). Ставить их я не буду и
ссылок не дам.

**Практическая замена, которая честно закрывает ту же задачу:** тестовый
**Java-клиент через Geyser**. Ваш сервер уже принимает Bedrock через
Geyser — значит, на проверки приходят те же пакеты. Моды для Java-клиента
(например, Meteor) работают на этом уровне и позволяют воспроизвести
KillAura, Fly, Speed, NoFall, Scaffold.

Оговорка, которую надо знать: Java-мод через Geyser **не** воспроизводит
Bedrock-специфику — тач-ввод, мобильные лимиты, особенности NetherNet.
То есть он проверяет логику проверок, но не их поведение на живом
Bedrock-клиенте. Для последнего нужен реальный телефон и реальный ПК.

## Что я НЕ делаю и почему

Не соберу «тестовый чит» даже с пометкой «для тестов». Причина не в
недоверии к вам — а в том, что артефакт неотличим от боевого: файл `.mcpack`
или DLL, который умеет KillAura, работает одинаково у тестировщика и у
читера. Права администратора сервера не дают права распространять такой
инструмент, и «для тестов» этого не меняет.

Проверять античит при этом можно полноценно — всё, что выше в разделах
1–3, работает без единого чита и даёт более полезный результат: оно
тестирует **ваш** код, а не чужой.
