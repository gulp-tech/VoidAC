# VoidAntiCheat 2.0.4 — что он умеет, насколько силён, как оптимизирован

Документ собран по **коду** собранного плагина (24 класса, оф. сборка
`vac-2.0.4-compat`), а не по описаниям. Где оценка — она названа оценкой.

---

## 1. Что античит умеет

### 19 проверок в 4 группах

| Группа | Проверка | Что ловит | По умолчанию |
|---|---|---|---|
| **Бой** | `reach` | удар дальше досягаемости (глаз → ближайшая точка хитбокса) | вкл |
| | `killaura` | серии ударов по нескольким целям, удары сквозь стены | вкл |
| | `autoclicker` | аномальный CPS и слишком ровный ритм кликов | вкл |
| | `velocity` | AntiKnockback: фактическое перемещение меньше ожидаемого отброса | вкл |
| **Движение** | `speed` | бег быстрее допустимого (token bucket, а не мгновенный лимит) | вкл |
| | `fly` | полёт/зависание без элитры, креатива, левитации | вкл |
| | `step` | шаг выше ванильного (0.6) | вкл |
| | `jesus` | ходьба по воде/лаве | вкл |
| | `spider` | лазание по стенам без лестницы | вкл |
| | `noclip` | проход сквозь блоки (Phase) | вкл |
| | `nofall` | отсутствие урона при падении ≥5 блоков | вкл |
| | `elytra` | управляемый полёт на элитре (ElytraFly) | вкл |
| | `vehicle` | разгон лодки/вагонетки (значения по типу поверхности) | вкл |
| | `timer` | ускорение игрового времени | вкл |
| **Мир** | `fastbreak` | слишком быстрое разрушение (Nuker/FastBreak) | вкл |
| | `fastplace` | слишком быстрая установка блоков | вкл |
| | `scaffold` | блоки строго под ногами на скорости, серией | вкл |
| | `blockreach` | блок дальше серверной руки | вкл |
| **Пакеты** | `badpackets` | физически невозможные данные (NaN, скачки >24 бл.) | вкл |

Плюс модуль **`anti-esp`** (скрытие сущностей за стенами) — **выключен по
умолчанию** и не проверен на клиенте.

### Управление

`/vac`, `/vac info <ник>`, `/vac alerts`, `/vac reset <ник> [проверка]`,
`/vac setback <ник>`, `/vac check <id> [on|off]`, `/vac world list|add|remove|only|clear-only`,
`/vac reload`, `/vac help [команда]`.

Права: `voidanticheat.admin`, `.alerts`, `.bypass` и отдельный `.bypass.<проверка>`
на каждую из 19.

### Три независимых слоя

```
детект  →  коррекция  →  наказание
(всегда)   (enforcement)  (auto-punish, выкл)
```

Это и есть то, что позволяет первый запуск в режиме «только алерты».

## 2. Уровень защиты по функциям

Шкала: **сильно** — устойчивый детект с контекстом; **средне** — ловит
типичные реализации, обходится аккуратной; **слабо** — только грубые случаи;
**нет** — не покрыто.

### Бой

| Чит | Уровень | Почему так |
|---|---|---|
| Reach (дальний удар) | **сильно** | мерится до **ближайшей точки хитбокса**, а не до центра; окно перемотки 800 мс компенсирует пинг обоих; компенсации на пинг, на скорость цели и на джиттер, потолок ×1.30 |
| HitBox (увеличенный хитбокс) | **средне-сильно, косвенно** | прямого замера нет, но завышенный хитбокс превращается в завышенный Reach и ловится им же |
| KillAura (мультиаура) | **средне** | порог 5 разных целей за 1 с, на ядре с Bedrock-боёвкой — 9. Одиночную аккуратную ауру не поймает |
| KillAura сквозь стены | **средне** | линия до цели проверяется по блокам, но только при пинге <320 мс |
| AutoClicker | **средне** | CPS-лимит (24 мышь / 27 тач) + проверка ровности; на тач-вводе ровность **не** проверяется — намеренно |
| AntiKnockback / Velocity | **средне** | сверяет ожидаемый отброс с фактическим за 5 тиков; серверные подбросы исключены |
| TriggerBot | **нет** | отдельной проверки нет |
| Aimbot / AimAssist | **слабо** | два грубых артефакта поворота (рывок и повтор), не полноценный aim-анализ |
| Criticals (пакетные) | **нет** | сознательно не реализовано |
| SuperKnockback | **слабо** | ловится только через общий порядок пакетов |
| KeepSprint | **слабо** | только через Velocity-сверку |

## 3. Оптимизация

### Архитектурные решения

| Механизм | Как работает | Эффект |
|---|---|---|
| **Затухание улик** | VL уменьшается каждую секунду (`decay-per-second` 0.08–0.16) | нет накопления «на всю жизнь» — нет ложных банов после лага |
| **Общий буфер** | `buffer` 1.5–3.0 очков до первого VL | одиночный выброс не даёт улики |
| **Sample gap** | не чаще одного полного очка за 80/120/220 мс (блок/бой/движение), остальное ×0.25 | телефон с пачками пакетов не «заливает» буфер |
| **Грейсы событий** | вход 3.5 с, телепорт 1.75 с, респавн 3.5 с, смена мира 2.5 с, velocity 0.9 с | телепорты `VoidAuthSpawn`, RTP, данжи не флагаются |
| **TPS-guard** | ниже 16 TPS проверки движения не штрафуют | лаг сервера не становится виной игрока |
| **Джиттер-адаптация** | до +30% к допуску при нестабильном канале | мобильный интернет |
| **Исключение миров/регионов** | маски `world`, `arena-*`, `*_test`, `lobby?` + WorldGuard-регионы | античит молчит там, где должен |
| **Сброс чистых состояний** | 90 с без улик → полный сброс | долгая память не копится |

### Ресурсы

- **2 задачи планировщика**: `secondTick` (раз в секунду) и `anti-esp` (выключен).
- **0 своих потоков**, всё в основном потоке — значит нет гонок и нет
  необходимости в синхронизации.
- **O(1) на событие**: буферы и счётчики, никакого полного перебора
  сущностей в горячем пути.
- **Данные по игроку** удаляются при выходе и дополнительно подчищаются в
  `secondTick`, если `QuitEvent` потерялся.
- **История цели для Reach** ограничена окном 800 мс, а не растёт бесконечно.
- API сервера в JAR: **0 файлов** (проверено в CI), т.е. нет вторых копий
  библиотек, нет конфликтов классов.

**Честная оценка нагрузки:** порядка **0.1–0.3 мс на игрока за тик** на
типичном сервере — на глаз по коду, **не** замерено профилировщиком. На 100
игроков это 10–30 мс/тик из 50 доступных, т.е. заметно, но не критично.
Реальный замер нужно снимать на вашем сервере (`/vac` показывает TPS, но не
время проверок — таймингов в плагине нет).

### Отдельно про «Disabler»

У ProtoHax и Apollon в списке модулей есть **Disabler** — модуль, который
ломает античиты. Против VAC он не проверялся. Что важно: VAC не полагается на
один сигнал, а требует **устойчивости** (буфер + sustain + 3 окна для Timer),
поэтому классические «дёрнуть пакет и сбросить счётчик» работают хуже. Но это
рассуждение, а не результат теста.

## 5. Честные ограничения

1. **Ничего не проверено на живом сервере.** Все оценки — по коду и по
   публичным спискам модулей клиентов, а не по результатам обкатки.
2. **Слабые места названы выше честно:** Blink, AimBot, пакетные Criticals,
   ChestStealer, AutoTool, BlockReach (из-за конфига ядра).
3. **Толерантность к Geyser — это компромисс.** Терпимость к пачкам пакетов
   (Timer ×1.5 и 3 окна, грейсы, джиттер) снижает ложные срабатывания на
   телефонах, но и делает Blink менее заметным. Осознанный выбор в пользу
   «не банить честного игрока».
4. **`anti-esp` выключен** — пока он выключен, защита от ESP/базового детекта
   по сущностям **не работает**. Встроенный Anti-Xray ядра — другая функция и
   его не заменяет.
5. **BlockReach фактически не срабатывает** при текущем
   `bedrock.anti-ghost-blocks.reach-tolerance: 2.25` в конфиге ядра; ужесточать
   нужно там, а не в античите.
