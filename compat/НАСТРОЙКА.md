# VoidAntiCheat 2.1 — настройка без правки jar

Всё ниже делается в `plugins/VoidAntiCheat/config.yml` + `/vac reload`,
либо командами на лету. Пересобирать jar не нужно ни для чего из этого списка.

## Команды

| Команда | Что делает |
|---|---|
| `/vac reload` | перечитать `config.yml` (пороги, миры, AntiESP, компенсация) |
| `/vac check <проверка> [on\|off]` | включить/выключить проверку **на лету** |
| `/vac check` (без аргументов) | список всех проверок |
| `/vac world list` | какие миры исключены и какой whitelist |
| `/vac world add arena-*` | добавить маску мира в исключения **(пишется в config.yml)** |
| `/vac world remove arena-*` | убрать маску |
| `/vac world only lobby survival` | проверять только эти миры |
| `/vac world clear-only` | снять whitelist (проверять везде) |
| `/vac alerts` | вкл/выкл алерты себе |
| `/vac info <ник>` | VL/буферы/пинг/устройство |
| `/vac reset <ник> [проверка]` | сбросить VL |
| `/vac setback <ник>` | принудительный возврат |

### Справка у каждой команды

Своя строка `usage`, своя справка и своё право — всё в конфиге, без правки jar:

```yaml
messages:
  usage-format: "&cНе хватает аргументов: &f{usage}"
  unknown-subcommand: "&cНеизвестная подкоманда: &f{sub}"
  usage:                       # краткое использование для сообщения
    info: "/vac info <игрок>"
    reset: "/vac reset <игрок> [проверка]"
    # ... по одной строке на команду
  command:                     # подробная справка: /vac help <команда>
    info:
      - "&f/vac info <игрок>"
      - "&7  VL и буферы, пинг, джиттер, допуск, устройство."
      - "&7  Право: &fvoidanticheat.admin"
    # ... по списку на каждую команду (info, alerts, reset, setback,
    #     check, world, reload, help)
```

`/vac help [команда]` — общая справка или по одной команде. При нехватке
аргументов печатается «чего не хватает» + справка именно этой команды
(раньше выводилось «игрок не найден», что сбивало с толку). Неизвестная
подкоманда теперь явно называется, а не молча показывает общий список.

### Автодополнение (Tab)

Работает на всех позициях и ничего не подсказывает сверх принимаемых
аргументов:

| Ввод | Подсказка |
|---|---|
| `/vac <Tab>` | `info, alerts, reset, setback, reload, check, world, help` |
| `/vac check <Tab>` | все 19 ключей проверок |
| `/vac check reach <Tab>` | `on, off, status` |
| `/vac world <Tab>` | `list, add, remove, only, clear-only` |
| `/vac world add <Tab>` | имена существующих миров + маски `arena-*`, `*_test`, `lobby?`, `minigames-*` |
| `/vac world remove <Tab>` | **только то, что уже в** `excluded-worlds` |
| `/vac world only <Tab>` | имена существующих миров |
| `/vac info|setback <Tab>` | ники онлайн-игроков |
| `/vac reset <ник> <Tab>` | все 19 ключей проверок |
| `/vac help <Tab>` | список команд для справки |
| `/vac check reach <Tab>` | `off` первым, если проверка включена |
| `/vac alerts <Tab>`, `/vac reload <Tab>` | пусто (лишних аргументов нет) |

Список не показывается игрокам без `voidanticheat.admin`, дубликаты
убираются, результат сортируется без учёта регистра и обрезается до 100
пунктов (у Bedrock-клиента окно подсказок небольшое).

`/vac world add|remove|only|clear-only` сразу сохраняют конфиг и применяют
изменение к онлайн-игрокам: у тех, чей статус «исключён» изменился,
обнуляется состояние движения — иначе после выхода из «тихого» мира
накопленная скорость дала бы ложное срабатывание на первом шаге.

## Миры, где античит не работает

Два способа, оба с масками (`*` — любое число символов, `?` — один символ,
регистр не важен):

```yaml
settings:
  # Проверять везде, кроме перечисленных
  excluded-worlds: [arena-*, "_test", world_the_end]

  # ИЛИ проверять только эти (приоритетнее, если не пусто)
  only-worlds: [survival, lobby?]
```

Примеры масок:

| Маска | Совпадёт с |
|---|---|
| `world` | только `world` |
| `arena-*` | `arena-1`, `arena-pvp`, `arena`… |
| `*_test` | `flat_test`, `pvp_test` |
| `lobby?` | `lobby1`…`lobby9`, но не `lobby10` |

Проверка идёт по имени мира, поэтому телепорт, смена мира и повторный вход
ничего не ломают. WorldGuard-регионы исключаются отдельно:
`settings.excluded-worldguard-regions`.

## Проверки

Каждая проверка настраивается независимо в `checks.<id>`:

```yaml
checks:
  reach:
    enabled: true
    buffer: 2.5          # сколько улик до первого VL
    max-vl: 20
    decay-per-second: 0.12
    setback-vl: 3.0      # при каком VL возвращать назад (0 = не возвращать)
    cancel-vl: 2.0       # при каком VL отменять действие (0 = не отменять)
    punish-vl: 0         # 0 = никогда не наказывать
    punish-commands: []  # свои команды наказания
```

`checks.default` задаёт значения по умолчанию для всех.
`/vac check <id> off` — быстрый способ выключить проверку без правки файла;
состояние живёт до `/vac reload` или перезапуска (файл остаётся источником
правды).

## Anti-ESP

```yaml
anti-esp:
  enabled: false                  # включать только осознанно
  only-if-core-inactive: true     # не запускаться, если Anti-ESP ядра активен
  interval-ticks: 10              # чаще не нужно: стабильные пары не трогаются
  join-grace-ticks: 60
  min-distance: 0.0
  max-distance: 96.0
  hide-spectators: true
  hide-invisible: true
```

В ядре уже есть свой Anti-ESP (`PurpurBedrockAC`, `protection.anti-esp`).
Два владельца видимости дают мигание игроков и лишние пакеты, поэтому модуль
по умолчанию не запускается при активном Anti-ESP ядра (пишет строку в лог).
Хочешь вести здесь — выключи в ядре и поставь `only-if-core-inactive: false`.

Anti-ESP — профилактика против ESP-паков (Apollon/Horion/Toolbox), а не
доказательство чита: VL за сокрытие не начисляется.

## Сеть и компенсация

```yaml
compensation:
  unknown-ping-assumed-ms: 120   # чем считать пинг, если он 0/неизвестен
  ping-factor-per-100ms: 0.020
  max-ping-factor: 0.12
  jitter-factor-per-ms: 0.0012
  max-jitter-factor: 0.30
  spike-interval-ms: 900
  unstable-hold-ms: 2500
```

## Боёвка на этом ядре

Ядро снимает кулдаун атаки для Bedrock на уровне NMS
(`bedrock-combat.enabled = true` по умолчанию), VoidPvP добавляет `ATTACK_SPEED`.
Поэтому:

```yaml
settings:
  core-zero-attack-cooldown: true   # не считать сырой CPS автокликером
combat:
  autoclicker-cps: 24               # порог для мыши/геймпада
  autoclicker-touch-cps: 27         # для сенсора и неизвестного устройства
  killaura-multi-targets: 5         # обычный сервер
  killaura-multi-targets-bedrock-combat: 9  # когда ядро включает bedrock-боёвку
```

Требование «ноль ложных» и «ловит всё» одновременно невыполнимо: чем мягче
пороги, тем тише ложные срабатывания и тем больше читов проходит. Начинай с
`enforcement: false` (только алерты), смотри `/vac info`, потом ужесточай.
